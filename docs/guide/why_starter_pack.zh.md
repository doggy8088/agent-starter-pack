# 為何需要 Agent Starter Pack？

許多開發者能快速建立初始的生成式 AI 代理原型——建立一個基本的聊天機器人或 RAG 系統可能感覺很直接。
**然而，從原型到穩健、可靠、可供生產的代理，這段旅程會出現重大挑戰。**

## 生產鴻溝：數據洞察

讓我們看看部署生成式 AI 代理的實際情況：
*   **3 個月：** 我們 (經驗豐富的 GCP 開發者) 將一個 *虛擬* 生成式 AI 代理轉變為可供生產狀態所需的時間。
*   **3-9 個月：** 我們觀察到開發者將其*實際*生成式 AI 代理投入生產的典型時間範圍 (這還不包括最終被放棄的專案)。

**為何需要如此大量的時間投入？**

## 「最後一哩路」的挑戰
根據我們的經驗以及開發者的回饋，真正的挑戰不在於初期的 AI 實驗，而是在於滿足生產部署的全面要求——即最終實現商業價值的「最後一哩路」：

![why_starter_pack](../images/why_starter_pack.png)


1.  **客製化與整合：**
    *   **業務邏輯：** 根據特定的業務需求和流程客製化代理的行為。
    *   **資料基礎：** 安全地將代理連接到相關、高品質且即時的公司資料。
    *   **安全與合規：** 實施穩健的資料隱私控制、存取管理以及對抗性攻擊的防護措施。

2.  **嚴謹評估：**
    *   **性能測量：** 在代理上線*之前*，定義指標並系統性地評估代理的品質、準確性和安全性。
*   **資料集生成：** 通常需要建立合成或策展的資料集，以進行徹底的評估和微調。

3.  **部署與營運 (MLOps/LLMOps)：**
    *   **基礎設施：** 建構可擴展、具彈性且具成本效益的雲端基礎設施來託管代理。
    *   **CI/CD 與測試：** 建立自動化管線，用於持續整合、交付、全面測試 (單元、整合、負載)，並實現快速迭代和安全回滾。
*   **UI 整合：** 將代理無縫嵌入到使用者面向的應用程式中，以提供一致的體驗。

4.  **可觀察性與監控：**
    *   **性能監控：** 即時追蹤代理的營運狀況、延遲和資源消耗。
    *   **資料收集：** 捕捉使用者互動和代理回應，用於持續監控、評估和微調。
*   **使用者回饋：** 實施機制以收集和處理使用者回饋，用於持續改進。

## 使用 Agent Starter Pack 彌合鴻溝
為了解決這些常見且耗時的障礙，我們建立了 **Agent Starter Pack**。
核心理念很簡單：**您專注於您的核心代理程式碼**——定義*您的*特定 AI 應用程式的獨特邏輯、提示和工具——而**我們則提供模板基礎**，用於在生產環境中可靠執行所需的一切。


![why_sp_edited](../images/why_sp_edited.png)


您可以這樣想：

*   **您的重點 (核心代理)：**
    *   提示和 LLM 互動
    *   業務邏輯整合
*   代理編排 (LangGraph, CrewAI, Google ADK)
    *   工具和資料來源定義

*   **我們的基礎 (Starter Pack 模板)：**
    *   **部署與營運：** API 伺服器、服務選項、CI/CD 管線、IaC、測試
    *   **可觀察性：** 日誌記錄、追蹤和監控儀表板
    *   **評估：** Vertex AI Evaluation 整合
    *   **資料與 UI：** 儲存連線、向量儲存、UI 展示場
*   **安全性：** GCP 安全最佳實踐


## Agent Starter Pack 如何提供協助：

![prototype_to_prod](../images/prototype_to_prod.png)


*   **透過生產模式更快地設定：** 透過基於常見 Google Cloud 實踐的預建元件 (用於 API 服務、CI/CD 和可觀察性) 取得先機，節省大量設定時間。
*   **專注於核心代理邏輯：** 減少花費在基礎設施和MLOps上的時間，讓您的團隊更專注於精進您的代理的獨特提示、工具和功能。
